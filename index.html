二18 条痛点 → 6 大主题域（含对应表名）

主题域 A · 提成核算重构 P0

目标：把「算钱」拆成「记数据 + 配参数 + 自动汇总」三层，解决规则复杂、月底才见数、拆分靠手工的问题。

来源角色痛点（V1 原文要点）对应表
服务会计提成规则复杂（退单率/回款率/单价分级），月中不知道自己拿多少，只能等月底提成核算单提成明细
记账会计做账完成率考核不公平：服务会计每月完结就拿提成，记账会计要全部做完才有订单环节明细
记账会计做账与粘贴两个环节、可能两人做，提成靠 Excel 双列手工拆订单环节明细
记账会计账务完成率统计不了：谁做的、做了多少、完成率多少看不到订单环节明细提成核算单
主管/PL长管理提成复杂：团队量、管理系数（主管 2.5 / 经理 3）、退单率阈值全手工公式提成参数
主管/PL长带人提成（徒弟单 1 元/家给原带会计、1 元/家给部门经理）靠手工录；签单业绩人均 1.5 万门槛与 0.8%/1% 奖金比例没落表提成参数订单
部门经理提成核算表太复杂（五表合一），公式报错、手工录入、删除标记，算错难查提成核算单提成明细

验收标准：✓ 每月核算单按账期×人员自动生成，全流程零手工金额录入；核算结果可追溯（每行提成能点回来源记录）；月底核算时长 ≤ 2 小时。

主题域 B · 退单全流程状态化 P0

目标：退单从「线下拖着」变成「系统内带时限的状态流程」，财务确认、抄送、留痕完整。

来源角色痛点（V1 原文要点）对应表
服务会计退单意向收到后没人跟进，线下拖 3 个月才说处理不了，对接客户机会全没了退单申请退单处理记录
财务/核算退单确认后人工改状态，欠款金额手工确认，认款/付款全靠线下退单申请收款记录
主管/PL长团队退单率考核说不清楚（0.7%→90%、1.2%→80%、超 1.2%→60%），Excel 没有规则约束提成参数退单申请

验收标准：✓ 退单从发起起每个节点带时限（发起→PL长处理→部门长审批→财务确认→收款→改状态），超时自动提醒；首次处理情况（是否上门、上门日期、详情）必填留痕。

主题域 C · 客户欠款状态自动化 P0

目标：客户状态由收款与账期自动驱动，欠款名单自动生成、每月自动公布，收入按结算周期确认。

来源角色痛点（V1 原文要点）对应表
服务会计欠款客户名单每月手工盘点、手工公布，还要一个个登记回来客户收款记录
财务/核算欠款超过 3 个月不算收入，判断靠人记、靠人标；客户挂着欠款但收入照算客户收款记录
财务/核算回款率、退单率取数分散、口径不统一，Excel 公式口径容易改乱客户提成参数

验收标准：✓ 客户状态零人工标记；欠款客户列表按月自动生成并推送；回款率/退单率由系统按统一口径自动计算。

⚠ 口径冲突待确认：V1 两处说法不一致——财务期望写「欠款超过 3 个月不算收入」，客户表备注写「欠费 1 个月标记欠款，第 4 个月起不计提成不算收入」。需管理层明确「标记欠款」与「不计收入」各自的起点月数。

主题域 D · 日行程与交付闭环 P1

目标：日行程一页看全（当日行程+次日计划+完成情况+总结），目标量与完成记录联动，走访登记与打卡合并。

来源角色痛点（V1 原文要点）对应表
服务会计走访要单独再登记一遍，同一件事填两遍表订单环节明细
部门经理看不到每个人今天的行程、完成情况，日行程闭环闭不上、不直观，目标量没量化订单环节明细
会计助理凭证粘贴、装订、报税做了就忘，还要单独做表格登记，太费时间订单环节明细
会计助理不知道自己今天完成了多少目标量，做完不点就不算数订单环节明细

验收标准：✓ 日行程目标量与交付明细完成量联动，完成情况即时可见；走访打卡一次完成登记，无重复填表。

主题域 E · 管理看板 P1

目标：汇算清缴、年检、收款、交付进度自动汇总，按 PL/人员看完成率。

来源角色痛点（V1 原文要点）对应表
部门经理汇算清缴、年检进度靠人工统计，收款/交付完成率不知道订单结算明细收款记录

验收标准：✓ 汇算收款/交付进度看板按 PL、按人员汇总应收/实收/完成率，零人工统计。

主题域 F · 参数与口径治理 P2

目标：提成参数配置表带生效月份（换算系数、单价分级、管理系数、考核阈值全部参数化），调方案只改配置。

来源角色痛点（V1 原文要点）对应表
主管/PL长退单率、回款率考核阈值散落在表格批注里，调一次方案改一次公式提成参数

验收标准：✓ 所有考核阈值、系数、单价集中在参数表，带生效月份；历史月份按当时参数核算，参数变更可追溯。

四关键口径定义（需管理层逐条确认）

口径项建议定义依据 / 冲突点
欠款月数起点「标记欠款」= 最近一期应收未收满 1 个月；「不计提成/收入」= 第 4 个月起（自最近一期应收账期起算）待确认V1 内部冲突：财务写「超 3 个月」，客户表备注写「第 4 个月起」
回款率口径回款率 =（服务中+结转）/（服务中+结转+欠款），按金额算（非换算量）待确认V1 已给公式但未说明按客户数还是金额
退单率口径退单率 = 退单 /（服务中+结转+欠款）；「退单」= 走完流程的退单（非发起即算）待确认V1 公式分母与回款率一致，但「退单」定义需定死
考核时间窗口退单率/回款率考核按当月核算（0.7%→90%、1.2%→80%、超 1.2%→60%）待确认V1 未说明按月/季/累计，窗口不同结果差异大
结算方式月付×1 / 季付×3 / 年付×12，交付金额 = 月费金额 × 结算月数已明确（V1 表结构方案）
环节拆分做账与粘贴分人时各记一行（订单×账期×环节×执行人），提成按环节计算已明确（V1 记账会计期望）

七范围边界（不做清单，需管理层确认）

待确认 以下为建议边界，请管理层逐条勾选：

1. 不做独立 APP，仅 Web 端（含移动端适配页面）

2. 不直接对接银行流水 / 电子税务局 / 开票系统，收款与报税仍以人工录入为主

3. 不做财务记账（总账/凭证生成），只做业务侧提成与客户管理

4. 不替代工资系统，提成核算结果为「应发金额」口径，实际发放仍走现有人事流程

5. 不做跨部门（销售/市场）数据打通，本期只覆盖会计部
